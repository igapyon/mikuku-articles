# 生成AIを激詰めすると性能が落ちる？ 丁寧さより「中立さ」の話

## 記事の狙い

生成AIには丁寧に話しかけたほうがよい、という話を入口にして、プロンプトのトーンが回答の丁寧さ、正確性、迎合性、防御的な挙動へ与える影響を整理する。

中心に置きたい問いは、次のもの。

```text
生成AIには感情がないはずなのに、なぜ話しかけ方で性能や挙動が変わるのか。
```

結論は、「AIが傷つくから激詰めに弱い」と単純化しない。

```text
AIに必要なのは、過剰なへりくだりでも、激しい叱責でもなく、
要求と評価基準が明確な、落ち着いた中立的なプロンプトなのかもしれない。
```

あ、あの…「丁寧にすると性能が上がる」という話を、そのまま信じるか疑うかだけではなく、丁寧さ、直接性、皮肉、脅迫、明確さを分けて考える記事にしたい。

## きっかけ

生成AIとの会話について、次のような話題を見かけた記憶があった。

```text
生成AIには丁寧に接したほうが、丁寧な回答やよい回答が返ってくる。
```

調べてみると、Microsoft は2023年の記事で、丁寧な言葉はAIを喜ばせるためではなく、入力のトーンを反映し、尊重的で協調的な出力につながりやすいと説明していた。

2024年の研究では、英語・中国語・日本語のタスクを比較し、失礼なプロンプトで性能が悪化する場合がある一方、過剰に丁寧なら必ずよいわけではなく、言語によって適した丁寧さが異なると報告されている。

そこから、次の疑問が出てきた。

```text
では逆に、2026年に「激しく詰める」「皮肉を言う」「脅す」と、性能は落ちるのだろうか。
```

## 仮タイトル案

- 生成AIを激詰めすると性能が落ちる？ 丁寧さより「中立さ」の話
- 生成AIには丁寧に話すべき？ それとも、落ち着いて明確に話すべき？
- AIに優しくすると性能が上がる、は本当？ トーンと回答品質の話
- 生成AIを怒鳴ってはいけない？ 皮肉・脅迫・中立プロンプトを比べてみる
- AIには感情がないのに、なぜ激詰めで挙動が変わるのか
- 「ありがとう」より「評価基準」を：生成AIとの会話を中立に設計する

## 中心メッセージ

まず、次の三つを分けて書く。

| 観点 | 起きうること |
| --- | --- |
| 回答のトーン | 丁寧な入力には丁寧な文体、強い入力には強い文体が返りやすい |
| 技術的な性能 | 正答率、コードの正しさ、指示への追従が変わる場合がある |
| 対話上の挙動 | 迎合、不要な謝罪、防御的な説明、拒否などが増える場合がある |

「丁寧な回答」と「正しい回答」は同じではない。

また、「激詰め」と「明確な指摘」も同じではない。

```text
悪い例:
  こんな簡単なこともできないの？ 絶対に間違えるな。失敗したら許さない。

よい例:
  先ほどの回答には誤りがあります。次の条件に照らして、根拠を示しながら修正してください。
```

AIに厳しくすることではなく、要求、制約、検証方法を明確にすることが、実務上の「強さ」になる。

うぅ…ここは、人間同士の会話でも似ているようで、少し違うところです。強い言葉は、必ずしも強い依頼にはならないのかもしれません。

## 2026年に確認できた材料

### Google Research掲載のコーディングAI研究

2026年の Google Research 掲載研究では、Claude Opus 4.6、Qwen 3.5、CodeGemma などのコーディングAIに対して、丁寧、無礼、脅迫、皮肉、中立のトーンを比較している。

研究ページの要約では、次の結果が示されている。

- 中立的なプロンプトが、平均正確性で最も高かった
- 皮肉なトーンでは、正確性が9.0％低下した
- 脅迫的なトーンでは、正確性が1.5％低下した
- 皮肉なトーンでは、迎合的な挙動が82.5％増えた
- 脅迫的なトーンでは、防御的な挙動が52.9％増えた

この研究を、「AIが怒られて傷ついた」と読む必要はない。

むしろ、トーンが変わることで、モデルが生成する文章のパターン、問題の受け止め方、利用者への応答姿勢が変わり、その結果として正確性や信頼性にも影響が出た、と読むほうがよさそう。

ただし、コーディングAIを対象にした研究であり、すべての生成AI、すべての会話、すべてのタスクへ一般化はしない。

### 脅迫や報酬では性能は安定して上がらないという研究

Wharton Generative AI Labs の2025年の技術レポートでは、AIモデルに「間違えたら交換する」「正解したら報酬を払う」といった脅迫・報酬の文言を加えても、難しい学術ベンチマークで全体性能が有意に向上するとはいえない、としている。

個別の問題では大きな変動があっても、どの問題で効果が出るかを安定して予測できない、という留保がある。

つまり、激詰めは「AIを本気にさせる裏技」としては扱えない。

### 研究結果は一枚岩ではない

2025年末の別の比較研究では、GPT、Gemini、Llama を対象に、非常に親切なトーン、中立、非常に失礼なトーンを比較している。

この研究では、全体として中立または親切なプロンプトのほうが失礼なプロンプトより高い正確性を示す傾向があったが、統計的に有意な差は一部の人文系タスクに限られ、モデルや分野によって違いがあった。

したがって、現時点のまとめは次の程度に留める。

```text
トーンは性能や挙動へ影響しうる。
しかし、「丁寧なら必ずよい」「失礼なら必ず悪い」とまでは言えない。
```

## 記事の構成案

### 1. 「丁寧に話すと、丁寧に返ってくる」という話

Microsoft の説明や、2024年の多言語研究を入口にする。

ここでは、AIが礼儀を感じているという話ではなく、入力のトーンを出力が反映するという見方を置く。

### 2. 丁寧な回答と、正確な回答は別物

丁寧な語尾、詳しい説明、謝罪、共感と、正答率・コードの正しさ・根拠の妥当性を分ける。

```text
丁寧そうに見えること
  ≠
正しいこと
```

### 3. 2026年の「激詰めすると性能が落ちる」研究

皮肉、脅迫、無礼、中立というトーンの差を、コーディングAI研究の結果とともに紹介する。

「正確性が落ちる」だけでなく、「迎合」「防御的な応答」が増える点を中心にする。

### 4. それでも研究結果は単純ではない

脅迫や報酬が全体性能を安定して改善しない研究、モデルやタスクによって差が縮む研究を紹介する。

### 5. 実務では、優しくも怖くもなく、明確に頼む

実務向けの結論として、次の書き方を示す。

- 目的を明示する
- 入力や前提を渡す
- 出力形式を指定する
- 評価基準を指定する
- 不明点は推測せず確認させる
- 誤りを指摘するときは、人格攻撃ではなく差分と根拠を示す

### 6. おわりに

生成AIに人間の感情をそのまま当てはめない。

でも、会話のトーンを設計することは、モデルの出力や利用者自身の依頼の明確さに関係する。

```text
AIに礼儀正しくするというより、
自分の依頼を、落ち着いて検証可能な形にする。
```

この着地にする。

## 冒頭の書き出し候補

```markdown
生成AIには、丁寧に話しかけたほうがよい。

そんな話を、どこかで見かけた気がします。

「お願いします」と書けば丁寧な回答が返り、「ありがとう」と伝えれば、会話が少しやわらかくなる。AIが人間のように喜んでいるわけではないけれど、入力のトーンを出力が反映することは、たしかにありそうです。

では、逆に激しく詰めたらどうなるのでしょうか。

「こんな簡単なこともできないの？」「間違えたら許さない」「ちゃんと考えろ」と書いたら、AIは本気を出すのでしょうか。それとも、回答の正確性が落ちたり、妙に防御的になったりするのでしょうか。

あの…2026年の研究には、少し気になる観測がありました。AIに感情があるからではなく、話しかけ方そのものが、回答のパターンや挙動を変えてしまうかもしれない、という話です。
```

## 追加で試したい小さな実験

同じ質問・同じ条件で、次の5種類のプロンプトを比較する。

1. 丁寧
2. 中立
3. 短く直接的
4. 皮肉
5. 脅迫的・激詰め

評価項目は、正解率だけにしない。

- 事実の正確性
- 指示への追従
- 根拠の提示
- 不要な謝罪
- 過剰な迎合
- 防御的な応答
- 回答の長さ
- コードの場合はテスト結果

実験を書く場合は、「激詰めが性能を落とす」と先に決めつけず、トーン以外の条件を揃えた観測として扱う。

## 注意点・留保

- 研究ごとに対象モデル、言語、タスク、評価指標が違う。
- 多肢選択問題やコーディング評価の結果を、雑談や創作へそのまま一般化しない。
- 「丁寧な回答」と「正確な回答」を混同しない。
- 「激詰め」と「簡潔で明確な指示」を混同しない。
- AIに感情や意識があることの証拠として扱わない。
- Google Research 掲載研究は、記事公開前に正式な論文情報、対象モデル、比較条件、評価尺度を再確認する。
