# 28件は、作業を分けてきた記録でした

## 主題

- 28件は単なる機能数ではなく、作業を少しずつ分けてきた記録
- 一度きりの prompt に名前、発火条件、参照先、注意点を置き、次にも使える Agent Skill にする
- 運用・改善・更新を重ねることで、次の作業で迷いにくくなる

## 図解キーワード

- 一度きりの prompt
- 名前
- 発火条件
- 参照先
- 注意点
- Agent Skill
- 運用・改善・更新
- 次の作業で迷いにくくなる

## 関係・流れ・対比

```text
一度きりの prompt
  ↓ 名前・発火条件・参照先・注意点
次にも使える Agent Skill
  ↓ 運用・改善・更新
次の作業で迷いにくくなる
```

- 背景にある作業の流れは、書く・レビューする・人格や媒体を保つ → 開発作業とリポジトリ運用 → CLIや外部 service を扱う
- `igapyon-miku-scm`、`igapyon-mikuku-agent` は頻繁に使う例。`mikuproject`、`mikuscore` はこれから育てたい例

## 図解構造

- layout-family: cycle
- primary-relation: 一度きりの prompt を再利用可能な Agent Skill にし、運用・改善・更新を経て次の作業へ渡す循環

## グラレコ構図案

- 左: `一度きりの prompt` を小さなメモとして置き、`名前 / 発火条件 / 参照先 / 注意点` の4つのタグを流し込む
- 中央: 最大の変換図。`次にも使える Agent Skill` を大きな中心カードとして、その前後を太い矢印でつなぐ
- 右: `運用・改善・更新` から `次の作業で迷いにくくなる` へ戻る循環矢印。みくくを右側へ配置する
- みくくの表情・視線: 右側で小さな判断を渡していくことを説明する穏やかな表情。中央の Agent Skill カードを見る。手は空にする
- 吹き出し: 「小さな判断を、次の作業へ渡します…」

## 正確性メモ

- `28件` は機能数ではなく作業を分けてきた記録として扱う
- 発火条件、参照先、注意点などは記事本文にある要素だけを使う
- platform を一度に作った、という表現へ広げない

## 共通スタイル契約

- style-profile: mikuku-graphic-recording-v1
- 横長 3:2、左・中央・右の3領域、中央の変換と循環を最大化
- 背景は均一に明るい全面不透明の白〜薄いアイボリー、矢印とカードは淡い色、文字は濃色
- みくくは1人、物を持たず、短い吹き出しを1つ
