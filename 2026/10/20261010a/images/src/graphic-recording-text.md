# Agent Skillsで「活きたドキュメント」へ

## 主題

- 規約・ルール・チェックシートを、日々の仕事で使う。
- Markdownに整え、Agent Skillsとして、いつ・どう使うかを伝える。
- 文書に沿って点検・判断材料の整理・次の作業へつなぐ。
- 仕事で使われることが、文書を丁寧に書き、更新する動機になる。

## 図解キーワード

- 規約・ルール・チェックシート
- Markdown
- Agent Skills
- 点検
- 判断材料
- 条件付き修正
- 根拠と一緒に指摘
- 見逃しを減らす
- 判断の観点を共有
- 文書を更新

## 関係・流れ・対比

```text
規約・ルール・チェックシート
  → Markdownに整える
  → Agent Skills：いつ・どう使うか
  → 対応エージェントが文書を参照
  → 点検 → 判断材料 → 条件付き修正
```

- 読むのが後回し・記憶頼み → 依頼に応じて参照・見逃しを減らす。
- 日々の仕事で使う → 古い箇所に気づく → 文書を更新 → また仕事で使う。

## 図解構造

- layout-family: flow
- primary-relation: 規約・ルール・チェックシート → Markdown → Agent Skills → 文書を参照して点検・判断材料・条件付き修正
- secondary-relations: 人の記憶頼みから文書に沿う確認へ／仕事で使う → 文書を更新 → 次の仕事で使う循環
- label-priority: Agent Skills／活きたドキュメント／Markdown／点検／判断材料／条件付き修正

## 役割分担・判断軸

| 要素 | 役割 |
| --- | --- |
| 文書 | 決め事と判断の根拠 |
| Agent Skills | いつ・どう使うかをエージェントへ伝える |
| 対応エージェント | 文書に沿って点検し、判断材料をまとめる |
| 人 | 依頼・変更の許可・文書の手入れ |

- 修正の条件：編集できる環境／変更の許可／判断材料がそろう。
- 指摘には根拠を添える。確認漏れの軽減は助けであり、完全保証ではない。
- 担当者が変わっても、判断の観点を共有しやすくする。

## グラレコ構図案

- 左: 規約・ルール・チェックシートの3つの紙アイコンと「記憶頼み」「読むのが後回し」。下にMarkdownへ整える矢印。
- 中央: 最大の主図。Markdown → Agent Skills（いつ・どう使うか）→ 対応エージェント。そこから点検・判断材料・条件付き修正の3つの出力へ矢印。条件付き修正のすぐ下に修正の条件を囲みで添える。
- 右: 説明役みくくを十分な大きさで配置。上に吹き出し。周囲の小さな利点ラベルは「見逃しを減らす」「判断の観点を共有」。
- 最も大きく見せる主図: 文書からAgent Skillsを経て日々の点検・判断・条件付き修正へつながる流れ。
- みくくの表情・視線: 右下に1人。やさしく少し困り眉。顔と視線は左上の主図へ。物を持たない。
- 吹き出し: あの…文書に、また出番ができるんです。

## 正確性メモ

- 記事本文に明記された内容を使う。全自動・必ず遵守・漏れゼロなどの保証は足さない。
- 修正は編集環境・許可・判断材料がある場合に限定。
- Agent Skillsに対応したエージェントを前提とする。
- モデル名、価格、数値、日付、作成環境は画像の説明に足さない。
- 文書アイコン・チェック・矢印は視覚表現。エージェントは囲みと小さな歯車で表し、第二の人物を描かない。

## 共通スタイル契約

- style-profile: mikuku-graphic-recording-v1
- 画面: 横長 3:2、左・中央・右の3領域、主図を最大化
- 紙面: 均一に明るい白〜ごく薄いアイボリー、淡い暖色の紙らしさ、濃色の読みやすい文字、やわらかい手描き線。暗い周辺減光や文字の背後の陰影なし
- 情報密度: 短いラベルと関係線を十分に置く。余白だけの景色にしない
- みくく: 1人、説明役として読める大きさ、物を持たない
- 吹き出し: グラレコ構図案の文言を1つ使う
- 背景: 全面不透明
