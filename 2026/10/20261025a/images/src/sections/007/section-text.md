# 同じ形式名でも、実装差を隠さない

## 主題

- 図内題名: 実装の違いと、変換時の注意
- 同じ形式名でも記法やオプションの差がある。Office変換は構造を重視。HTMLのラスター画像は参照が既定、SVGは埋め込みが既定。

## 図解キーワード

- Node.js版 / Java版
- 記法・オプションに差
- --help
- 構造を重視
- ラスター画像
- SVG
- --image-mode embed
- リモート画像URLは不可

## 関係・流れ・対比

- Node.js版・Java版の実装差を確認 ＋ 形式ごとの変換上の注意を確認

## 図解構造

- layout-family: comparison
- primary-relation: Node.js版・Java版の実装差を確認 ＋ 形式ごとの変換上の注意を確認

## グラレコ構図案

- 左: 並列カード「Node.js版」「Java版」を同じ大きさにし、間に「記法・オプションに差」。
- 中央: 主図の中央は確認カード「使うCLIの --help と説明を確認」。下に「Office: 構造を重視 / ピクセル単位の再現ではない」。
- 右: 「HTML画像」の小さな表。「PNG・JPEGなど → 既定は参照」「--image-mode embed → 埋め込み」「SVG → 既定で埋め込み」「リモート画像URL → 不可」。
- 最も大きく見せる主図: 上記のprimary-relation。左右と中央の関係を明確にする。
- みくくの表情・視線: 画面の右下、または指定がある場合は中央下。画面の20%程度の大きさで1人。やわらかな少し照れた説明表情で主図を見る。キャラの外観は正本を維持。何も持たない。自然な空の手。
- 吹き出し: 使うCLIの説明も、確認します。

## 正確性メモ

- 対象セクションの本文だけに基づく。Node.jsとJavaの機能が完全一致する図にしない。画像の仕様は両実装の差と混同しないよう別枠。
- 設計文は印刷せず、題名・短いラベル・吹き出しだけを画像内に描く。出力形式カード同士を連続変換する矢印を描かない。足りない情報を別セクションから補わない。
