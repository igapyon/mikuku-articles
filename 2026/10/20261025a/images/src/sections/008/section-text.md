# Skillと変換CLIの役割を分ける

## 主題

- 図内題名: Skillが案内、CLIが変換
- 生成AIにHTML生成を直接頼むこともできる。変換をCLIへ任せて再現性とトークン消費抑制を狙い、AIなしの直接利用や複数Skillでの再利用も可能にする。

## 図解キーワード

- Agent Skill
- CLI
- 再現性
- トークン消費
- 生成AIなしでも実行
- 再利用
- 同じ版・入力・オプション

## 関係・流れ・対比

- 依頼 → Skillがツールを選択・実行案内 → CLIが変換 → 出力

## 図解構造

- layout-family: layers
- primary-relation: 依頼 → Skillがツールを選択・実行案内 → CLIが変換 → 出力

## グラレコ構図案

- 左: 上段は依頼→Agent Skill「選択・案内」、下段はターミナルやスクリプトからの直接利用。
- 中央: 主図は上下の経路が同じ「CLI:ファイルを変換」の箱へ入る2レーン構造。その先に出力書類。同じファイル処理を呼び出せることを強調。
- 右: 効果のカード「再現性: 同じ版・入力・オプション」「トークン消費を抑える狙い: モデルによる全文生成を減らす」「生成AIなしでも実行」「複数Skillで再利用」。
- 最も大きく見せる主図: 上記のprimary-relation。左右と中央の関係を明確にする。
- みくくの表情・視線: 画面の右下、または指定がある場合は中央下。画面の20%程度の大きさで1人。やわらかな少し照れた説明表情で主図を見る。キャラの外観は正本を維持。何も持たない。自然な空の手。
- 吹き出し: 案内と変換を、分けてみました。

## 正確性メモ

- 対象セクションの本文だけに基づく。トークン削減の数値や保証は描かない。Skillを使う処理自体にもトークンを使う。モデルやagentが一切不要という意味はCLI単独経路に限る。
- 設計文は印刷せず、題名・短いラベル・吹き出しだけを画像内に描く。出力形式カード同士を連続変換する矢印を描かない。足りない情報を別セクションから補わない。

## 共通スタイル契約

- style-profile: mikuku-graphic-recording-v1
- 横長3:2、左・中央・右の3領域、主図を最大化

- fully opaque background; no transparent or semi-transparent pixels
