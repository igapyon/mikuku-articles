# 日々の予定とタスクを、AIに話しかけて整える

## 主題

- `igapyon-miku-daybook` は日々の記録をAIエージェントに手伝ってもらう Agent Skill
- 予定・タスク・活動記録を、いつもの言葉で依頼してMarkdownに残す
- 今日の作業と、この先の予定を day-plan で見渡す
- 会話を閉じても手元の記録を読み返し、必要なら直せる

## 関係・流れ・対比

```text
自然な言葉でお願い
  ↓
igapyon-miku-daybook Skill が内容を整理
  ↓
Markdown の予定 / タスク / 活動記録を追加・更新
  ↓
必要なとき day-plan を生成
  ↓
今日の作業・近い予定・確認が必要なタスクを人が見る
```

## 記録の種類

- 予定: これからの日時や予定
- タスク: これから行う作業
- 活動記録: すでに行ったこと
- 同じタスクがあれば、追加前に既存記録を探す

## 役割分担・判断軸

- 利用者: いつもの言葉で依頼し、追加・更新された記録を確認する
- AIエージェント + Skill: 依頼を予定・タスク・活動記録に振り分け、daybookのルールに沿って扱う
- Markdown記録: 会話の外に残り、人もAIエージェントも後から参照・編集できる
- 判断の軸: 作業予定期間と外部締切を分ける。活動記録とタスク完了を分ける。
- day-planを作る前提: daybook側のスクリプト、Node.js、依存パッケージを準備する

## 日付と完了の区別

- 作業予定期間（開始日・終了日）と外部から決められた締切は別
- 1日だけの作業予定は開始日と終了日が同じ
- 仮の日程は仮であることを記録し、確認対象にする
- day-plan は作業予定期間を基準にする。タスク本文中の締切を自動では拾わない
- 活動記録に「明細をまとめた」と残しても、提出などが残るタスクは未完了

## day-plan

- 今日取り組む予定の作業
- 近々始まる作業
- 終了予定日が近いタスク
- これからの予定（対象日を含む1週間）
- 予定期間を過ぎた未完了タスク
- 日程の確認が必要なタスク
- day-plan はその時点の記録から作る一覧。同じ対象日で再生成すると上書き
- 残したいメモは元のタスクや予定へ書く

## 記録を後から使う

- 会話を閉じても、手元のMarkdownを人が読み返して編集できる
- 別の会話のAIエージェントも記録を参照できる
- 活動記録を週次報告の材料として整理し、人が元記録を見比べて仕上げる

## 任意の通知

- 同梱の GitHub Actions で day-plan を指定した GitHub Issue へ投稿できる
- 標準設定は日本時間の午前6時ごろが目安
- スケジュール実行には遅延や未実行があり、毎朝定刻に届く保証はない
- 投稿先などは利用するリポジトリに合わせて設定
- 会話での記録と day-plan を使い、必要なら通知を追加する

## グラレコ構図案

- 左: 利用者の依頼例を3つ配置（10月15日19時〜21時、○○ホールの練習会を予定に追加 / 交通費精算を追加、作業予定10月12日・提出締切10月16日 / 今日、交通費の明細をまとめたことを活動記録に残す）。例にない内容や日付は加えない。
- 中央: `igapyon-miku-daybook` Skill を入口に、予定・タスク・活動記録のMarkdownへ振り分ける大きな流れ。タスクと活動記録を別カードにする。
- 右: day-plan が今日の作業、近々1週間の予定、期間超過・要確認タスクをまとめる。人が確認し、必要なら元の記録を更新する。
- 下部の小さな補助図: 作業予定期間と外部締切、活動記録とタスク完了の違い。記録は会話の外に残り、週次報告の材料にもなる。GitHub Actions から Issue への通知は任意で、時刻は目安、遅延・未実行があり得ると注記。
- 最も大きく見せる主図: 自然な依頼 → Skill → 3種類のMarkdown記録 → day-plan → 人が確認、の一続きの流れ。
- みくくの表情・視線: 右側で安心した優しい表情。中央の記録からday-planへ進む矢印を見る。
- 吹き出し: 「まずは予定を一つ、言葉で残してみましょう…！」

## 正確性メモ

- Skillは記録帳そのものではなく、AIエージェントがdaybookを扱うルール。
- day-plan生成には、daybook側の生成スクリプト、Node.js、依存パッケージの準備が必要。
- day-planは本文に書かれた外部締切を自動抽出せず、作業予定期間を基準にする。
- 活動記録とタスク完了は別の意味。
- GitHub Actionsの投稿は任意設定で、実行時刻の遅延や未実行があり得る。
- day-plan再生成時は同じ対象日のファイルを上書きする。

## 共通スタイル契約

- style-profile: mikuku-graphic-recording-v1
- 画面: 横長 3:2、左・中央・右の3領域、主図を最大化
- 紙面: 均一に明るい白〜ごく薄いアイボリー、淡い暖色、濃色の読みやすい文字、やわらかい手描き線。暗い色かぶりや周辺減光なし
- 情報密度: 短いラベルと関係線を使う。小さな注意書きも読みやすく
- みくく: 1人、説明役として読める大きさ、物を持たない
- 吹き出し: 「まずは予定を一つ、言葉で残してみましょう…！」
