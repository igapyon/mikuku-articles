# PHP2Shellの仕組み

## 主題

- 処理が途中で止まったあとに残るものから、2件の脆弱性を理解する。
- 1件目は未完成のデータを終了処理が使用し、2件目は解放後も残った古い参照を次のリクエストが使用する。
- ワーカーの生存期間と、その中のデータの有効期間は異なる。
- 安全な地点で止めることと、次へ持ち越す内部状態をリセットすることが修正の要点。

## 関係・流れ・対比

```text
PHPワーカーは続く / リクエストごとのデータは入れ替わる

① CVE-2026-109618
初期化 → メモリ不足で中断 → 未完成のデータを終了処理が使用

② CVE-2026-109619
データを解放 → 古い参照が残る → 次のリクエストで解放後使用
                  └ 同じ場所に別のデータが入ると、以前の構造として誤って扱う

こうした食い違いを利用できる条件がそろう → コード実行につながる場合がある

修正: 安全な地点で止める / さらに高い上限ではプロセスを終了 / 内部状態のリセット
```

## 図解構造

- layout-family: flow
- primary-relation: 中断後に残る未完成のデータと古い参照を、2本の異なる処理の流れで並べる
- secondary-relations: PHPワーカーとデータの寿命の違い、条件付きのコード実行、修正による後片づけ
- label-priority: PHP2Shell、未完成のデータ、古い参照、次のリクエスト、解放後使用、安全な地点

## 役割分担・判断軸

- CVE-2026-109618: 初期化が終わらないまま、そのリクエストの終了処理が未完成のデータを使う。
- CVE-2026-109619: 使い終えたメモリへの参照が残り、同じワーカーの次のリクエストが通常の初期化より前に使う。
- 2件の経路を区別する。1件目まで必ず次のリクエストで発生するようには描かない。
- コード実行の成立条件はPHPの動かし方やアプリケーションによって異なり、実行権限はWebワーカーの権限。

## 正確性メモ

- 記事本文だけを説明内容の根拠にする。世界全体の影響規模、修正バージョン、評価点、利用モデル、未記載の数値は追加しない。
- 解放後使用を詳しく示すのは2件目の経路。1件目と2件目を同じ原因へまとめない。
- 「条件がそろうと」「成立条件は環境で異なる」を残し、必ずコード実行できるという図にしない。
- 下段の「別データへ再利用」は解放後使用の一般的な仕組みを説明する小さな補図とし、詳細な攻撃手順は描かない。
- 修正欄は「安全な地点で止める」「さらに高い上限では終了」「内部状態のリセット」。修正が全プロセスを毎回終了するようには描かない。
- 正確性メモ、レイアウト設計語、モデル情報は画像へ印刷しない。
