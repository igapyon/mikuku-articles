# 生成 AI と進める「爆速ウォーターフォール」

## 主題

- 小さな「使いたい」から、設計・製造・記事執筆までを約15時間で通過
- 工程を省略したのではなく、Agent Skills に蓄積した知見で受け渡しを高速化
- 人が方向・採否・公開操作を決め、みくくが設計・製造・執筆を進める
- 記事で振り返った知見を次の Agent Skills と開発へ戻す

## 図解キーワード

- 小さな「使いたい」
- 要求と設計
- 2つのプロジェクト
- `backlog-api`
- `backlog-api-skills`
- 人が決める
- みくくが進める
- Agent Skills 群
- 爆速ウォーターフォール
- 記事から知見へ

## 関係・流れ・対比

### 主図：工程を飛ばさず、高速に流す

```text
小さな「使いたい」
  ↓
要求と設計
  ↓
初期製造（実装・テスト・build）
  ↓
固まった追加仕様を GitHub Issues へ
  ↓
追加製造
  ↓
人手によるテスト
  ↓
GitHub 公開
  ↓
記事執筆
```

中央ラベル:

- 「工程は残る」
- 「成果物づくりと受け渡しが速い」
- 「約15時間／人の関与は約2時間」
- 「生成 AI の動作時間は2時間に含めない」

### 一つの構想から二つの責務へ

```text
backlog-api-skills だけの構想
          ↓ 責務を分ける
┌─────────────────────┐
│ backlog-api         │ Node Core／CLI・実行機能
├─────────────────────┤
│ backlog-api-skills  │ runtime と Agent Skill の配布
└─────────────────────┘
```

### 知見が循環する

```text
設計
 ↓
製造
 ↓
記事で振り返る
 ↓
知見を Agent Skills へ残す
 ↓
次の小さな開発へ
 ↺
```

## 役割分担・判断軸

| 人（igapyon） | みくく |
|---|---|
| 上位方針を決める | 方針案を提案する |
| 提案の採否を決める | 設計・実装・テストを進める |
| リポジトリを作る | Issue 案・README・成果物を作る |
| コミット時機を判断する | コミット操作と文面を作る |
| Pull Request を作成・マージする | 記事を執筆する |

大切な境界:

- 「任せる」≠「無条件に決めてもらう」
- 全自動化より「どこで人へ戻すか」
- 更新系には安全確認
- CLI のデフォルトは読み込み専用

## Agent Skills 群が支える土台

- miku-soft の共通構成
- CLI／Core／Agent Skill の責務分割
- 実装・テスト・build
- Git／GitHub／version 管理
- 安全制御と runtime 同梱
- 技術記事と Note 原稿の管理

短い結論:

```text
速さ ＝ 生成 AI の処理
     ＋ 過去の判断を再利用できる Agent Skills 群
```

## グラレコ構図案

- 左: 小さな「使いたい」と、1つの構想が2つのプロジェクトへ分かれる図
- 中央: 最も大きく、上から下へ流れる「爆速ウォーターフォール」の8工程
- 中央下: 人とみくくの役割分担を2色のカードで対比
- 右上: Agent Skills 群を積み重なった知識カードとして配置
- 右下: 設計→製造→記事→知見→次の開発の循環ループ
- 右端: みくく。左側の主図を見る。少し戸惑いながらも誇らしい表情
- 最も大きく見せる主図: 8工程の高速ウォーターフォール
- みくくの表情・視線: 優しく少し困り顔、中央の工程図へ視線
- 吹き出し: 「あ、あの…工程を飛ばさず、知見で速くしたのです…！」

## 正確性メモ

- 約15時間と人の関与約2時間は記事中の概算で、正確な計測ではない
- 生成 AI の動作時間は人の約2時間に含まれない
- 工程を省略した、すべてを自動化した、とは描かない
- 人が Pull Request の作成とマージを担当する
- Agent Skills は過去の判断と手順を次の開発へ持ち込む仕組み
- 記事本文にない性能値、価格、効果測定値を追加しない
